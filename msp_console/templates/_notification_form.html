Delivery method

How to set up Microsoft 365 sending (no user sign-in needed)
  1. In the Entra admin center go to App registrations > New registration. Single tenant, no redirect URI.
  2. Copy the Directory (tenant) ID and Application (client) ID from the Overview page into the fields above.
  3. Under Certificates & secrets create a client secret and paste its Value (not the Secret ID) above.
  4. Pick the mailbox alerts are sent from, for example acme-alerts@yourdomain.com. A shared mailbox works and needs no license. Enter it as the sender below.
  5. Allow the app to send mail, scoped to that one mailbox (recommended). The Microsoft Graph Mail.Send application permission lets an app send as any mailbox in the tenant. Instead of granting it tenant-wide in Entra, use Exchange Online RBAC for Applications: New-ServicePrincipal, a New-ManagementScope that matches only the alert mailbox, then New-ManagementRoleAssignment with the Application Mail.Send role, and check it with Test-ServicePrincipalAuthorization. Do not also leave an unscoped Mail.Send grant in Entra, because the two add together.
  6. Quick alternative (lab/testing only): Entra API permissions > Add a permission > Microsoft Graph > Application permissions > Mail.Send, then Grant admin consent. This allows sending as any mailbox.
  7. Use Test connection (checks the app can sign in) and then Send test email (proves the mailbox can send).

Why not SMTP for Microsoft 365? Exchange Online is retiring Basic authentication for SMTP AUTH; Graph with OAuth is not affected.
